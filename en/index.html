Products

Four products ready to build on the base.

Not concepts: each has code, executed cases and numbers measured in this repository. Together they cover the whole cycle — capture the physics, accelerate the answer, prove it is right, and follow the asset over time.

Available

Product 01 · CFD

PINNeAPPle CFD

The complete CFD workflow, E1 to E11: you describe the problem, the pipeline builds geometry and mesh, runs OpenFOAM, generates the dataset, trains the surrogate and closes with the VeriPhysics evidence map. Built for pipe erosion, aerodynamics and heat transfer.

  • Erosion in a 90° bend: simulation between 1.05× and 1.49× the published experiment — inside the factor-2 band industry accepts. The hand formula, in the same regime, is off by about 100×.
  • Full campaign: 32 simulations from geometry to trained model ran in 23 minutes, and the surrogate answers in milliseconds with 1.0% error on pressure drop at unseen points.
  • Journey frontend: seven steps for the client, plus a detailed mode for the engineer, with mandatory login in production.
  • Closed deployment: a single Docker image with API and screens, host OpenFOAM via Docker, and an email with a PDF report at the end of each run.

Product 02 · Surrogates

Surrogate Studio

Turns the simulations your team already ran into a model that answers in microseconds — and is checked against the solver on every delivery, never against itself. This is the product that replaces “wait for the solver” with “adjust the design now”.

  • ~200,000× faster than the real 3D simulation across seven heat-sink geometries, with 4.46% mean error and 7.35% worst case against FEniCS/dolfinx.
  • Reproducible: temperature prediction is deterministic — 4.46%/7.35% identical across three runs on different days. Only the speed-up factor moves with machine load.
  • Vehicle aero twin: ten real OpenFOAM runs reduced to 6 POD modes, with 0.05% error on the velocity field and 0.17% on Cd, including the inflection above 44 m/s.
  • Physics in the middle of the network: 4.5% mean error against 3D finite elements on cases it never saw in training.

Product 03 · Verification

VeriPhysics

The quality gate that sits between the result and the decision. It takes a trained model, a CFD case or an FEA deck and returns one score per check — physics residual, convergence, calibration, coverage — with the real number and source behind each. A check that did not run shows as “not run”, never as a fabricated score.

  • Caught what the loss hid: on an already-trained wear model from a real client, the training loss looked healthy while the physics residual sat hundreds of times over a trustworthy threshold — the network learned to hit the target while violating the equation along the way.
  • Simulation preflight: an unsupported beam finishes with “Job finished” and a displacement of 1.8e11 mm; the checklist flags FAIL before you lose the afternoon.
  • Mesh quality: metrics identical to OpenFOAM's checkMesh (pitzDaily: skewness 0.260575, non-orthogonality 5.95°).
  • Convergence and lineage: five real runs on OpenFOAM v1912 and CalculiX 2.21 correctly classified — converged, cut at 60 iterations, diverged after 5, a transient with Courant 0.85, and a nonlinear cantilever in 6 increments.

Product 04 · Digital twin

PINNeAPPle Twin

The digital-twin line, in two layers. Twin Runtime puts a validated model to work next to operational data. The commissioning layer closes the cycle on top of it: a signed contract, a preflight that can refuse, a backtest against an instrument the filter never sees, and filed evidence — which is what turns a runtime into a closed product.

  • A runtime that runs: EnKF, forecasts with 5–95% bands, an alert on the normalised innovation (χ² at 99.9%), validity checks and revalidation, history in SQLite or Postgres, MQTT, REST and OPC UA.
  • An acceptance gate: 11 preflight checks — swapped unit, frozen channel, under-determined estimate, a declared sampling rate the history never produced — plus a backtest against the redundant probe. If it does not pass, it does not go on line.
  • HX-201, a fouled exchanger: 0.216 °C RMSE (0.54% of span) and fouling estimated at 0.001651 ± 0.000010 against a true 0.001637, with the redundant probe kept out of the filter.
  • An honest band: 95.5% of validation readings inside the band, calibrated on the preceding 35.4 h and measured on the hours after. The raw band covered 86.4% — that number is printed beside it, not hidden.
  • Alarm by projection: extrapolating the latent state warned 2.6 h before the measured crossing, and the error of that forecast (1.1 h) is reported with it. The NORMAL → WATCH → ALARM → RECALIBRATE ladder has hysteresis, and the latent state goes out as AAS (BaSyx SDK), DTDL, NGSI-LD, Eclipse Ditto and OPC UA.

Get started

The equation goes in as text. The error comes out measured.

One-command install, no build. The same package runs the problem, the training, the comparison against the solver and the report export.

inverse_heat.py 
# the h nobody measures, from a handful of thermocouples
from pinneapple_physics import HeatConduction1D
from pinneapple_neural import PINNTrainer

problem = HeatConduction1D(
    conductivity=50.0,          # W/(m·K)
    length=0.30,                # m
    learn_h=True,              # h enters as a trainable parameter
)

model = PINNTrainer(problem, layers=[3, 64, 64, 1])
report = model.fit(thermocouples=readings, epochs=5000)

print(report.h, report.h_std)   # 14.8 0.3  (true value: 15)
report.verify_against("finite-volume")   # per-field error, error map
# checks physical consistency and convergence, not just "did it solve"
from pinneapple_analysis.verification import physics_confidence_score as pcs

confidence = pcs.compute_physics_confidence(
    guardrail_report=guardrail_report,
    convergence_result=convergence_result,
)

# one score from 0 to 1 per check — never an average that
# hides a check that did not run
for check in confidence.checks:
    print(check.name, check.score, check.source)
# the end-to-end CFD pipeline, E1 to E11
$ pinneapple-cfd run --problem erosion-bend \
    --geometry bend_90.stl \
    --solver openfoam \
    --verify veriphysics

# the public, reproducible benchmark
$ python -m pinneapple.benchmarks.ssqn_helmholtz

# and the 248 examples, each with checked output
$ python run_all_examples.py

What you get on day one

  • A reproducible environment — 248 examples with a versioned _out, so you can compare byte for byte with your own result.
  • Public benchmarks — SSQN Helmholtz, LBM vortex shedding, LPM design space, latency and data I/O. No “internal benchmark”.
  • Navigable documentation — per-module reference, core concepts, guides, and the validation status of every capability.
  • Real interoperability — OpenFOAM, CalculiX, FEniCS/dolfinx, Gmsh, VTK, STL, USD and glTF in the same session.
